## 1. 개요

1.1 본 문서는 ㈜헤디가 2026년 10월에 회신한 4개 항목에 대하여, (주)에스와이유가
개발 중인 서버·수집 프로그램에 반영한 결과를 통보하고 미확정 사항의 확정을
요청하기 위한 것임.

1.2 회신 4개 항목은 아래와 같음.

| 번호 | ㈜헤디 회신 내용 |
|---|---|
| 1 | 시스템 구성 3안 제시 (모듈 직결 / 사용자 PC 경유 / 브릿지 경유) |
| 2 | 브릿지 내부 미전송 데이터 최대 1개월분 저장 가능 |
| 3 | 명령 응답은 네트워크 상태에 따라 다르나 1초 이내 |
| 4 | RS-485 브릿지당 최대 32대 지원, 현장 환경에 따라 영향받을 수 있음 |

1.3 4개 항목 전부 서버 측 반영을 완료하였으며, 반영 범위와 서버 동작은
제2항·제3항에 기재함.

## 3. 항목별 반영 상세

### 3.1 시스템 구성 3안 수용 (회신 1)

3.1.1 세 구성을 모두 수용하며, 한 현장에 세 구성이 섞여 있어도 동작함.
구성별로 서버를 따로 두지 않음.

| 구성 | 데이터 경로 | 토픽 | 서버 기록 |
|---|---|---|---|
| 1안 | 측정모듈 → MQTT → 서버 | `dh/v1/dh1/module/{모듈ID}/tele` | 연결 방식 "모듈 직결" |
| 2안 | 측정모듈 → RS-485 → 사용자 PC → MQTT | `dh/v1/dh1/gateway/{PC ID}/tele` | 연결 방식 "PC 경유" |
| 3안 | 측정모듈 → RS-485 → 브릿지 → MQTT | `dh/v1/dh1/bridge/{브릿지ID}/tele` | 연결 방식 "브릿지 경유" |

3.1.2 토픽이 발신 주체를, 페이로드가 대상 설비를 나타내도록 분리함.
연결 방식은 장비가 사용한 토픽을 보고 서버가 자동 기록하므로 별도 등록 절차가 없음.

3.1.3 1안과 같이 측정모듈이 자기 값 하나만 올리는 경우, `items` 배열 없이
최상위에 측정값을 담는 형태를 수용함. 이때 `deviceId` 는 생략 가능하며,
서버는 토픽의 발신자 ID 를 설비 식별자로 사용함.

3.1.4 상태(`stat`) 메시지도 세 주체 모두 수용함. 브릿지·사용자 PC 가 보내면
앞단의 상태로, 측정모듈이 직접 보내면 해당 설비의 상태로 기록함.

### 3.2 미전송분 최대 1개월 버퍼 재전송 (회신 2)

3.2.1 과거분을 뒤늦게 보낼 때의 서버 처리는 아래와 같음.

| 처리 | `replay: true` | `replay` 없음 |
|---|---|---|
| 이력 저장 | 수행 | 수행 |
| 현재값 갱신 | 수행하지 않음 | 수행 |
| 알람 발생 | 수행하지 않음 | 수행 |

3.2.2 한 메시지에 담을 수 있는 최대 항목 수를 500개로 두었음. 운영 화면에서
10~5,000개 범위로 조정 가능함. 상한을 넘으면 앞의 500개까지만 받고 나머지는
수신 내역에 경고로 남김.

3.2.3 재전송분은 한 건씩 처리하지 않고 일괄 적재함. 1개월분 전송 시에도
수집이 밀리지 않도록 한 조치임.

3.2.4 같은 `(설비, 측정시각)` 의 중복은 서버가 제거하므로, 재전송 구간이
기존 수신분과 겹쳐도 무방함.

3.2.5 수신 내역에 남기는 원문은 앞의 20개 항목까지만 보관하고 나머지는 건수로
적음. 1개월분 재전송으로 로그 표가 비대해지는 것을 막기 위함임.

### 3.3 명령 응답 1초 이내 (회신 3)

3.3.1 장비 규격(1초)과 서버 대기시간을 아래와 같이 분리하여 운용함.

| 항목 | 값 |
|---|---|
| 장비 응답 목표 | 1초 이내 (㈜헤디 회신) |
| 서버 대기시간 기본값 | 10초 |
| 서버 대기시간 조정 범위 | 1~120초 (운영 화면에서 변경) |
| 초과 시 처리 | 해당 명령을 "응답 없음"으로 정리 |
| 지연 도착 응답 | "응답 없음"으로 정리된 뒤 도착해도 정상 반영 |

3.3.2 대기시간을 장비 규격보다 넉넉히 둔 이유는 브로커 경유 왕복 지연과
무선 구간의 일시적 지연을 응답 실패로 오판하지 않기 위함임.

3.3.3 명령 응답에는 수신한 `cmdId` 를 그대로 반환하여야 함. `cmdId` 가 없는
응답은 어느 명령의 응답인지 특정할 수 없어 경고로만 기록됨.

### 3.4 RS-485 브릿지당 최대 32대 (회신 4)

3.4.1 앞단(브릿지·사용자 PC) 1대당 측정모듈 수용 한도를 32대로 두었음.

| 상황 | 서버 동작 |
|---|---|
| 등록 화면 | 앞단별 등록 대수를 `n / 32` 로 표시 |
| 한도 도달 | 해당 앞단을 선택 목록에서 비활성화, 등록 요청 거부 |
| 한도 초과 상태로 값 수신 | 값은 저장하고 수신 내역에 경고 기록 |

3.4.2 "현장 환경에 따라 영향받을 수 있음" 회신을 반영하여, 수용 한도를
앞단별로 개별 조정할 수 있도록 하였음. 특정 현장에서 32대를 낮춰야 하는
경우 서버 설정만으로 대응 가능함.

## 4. 서버 측 자체 검증 결과

4.1 아래는 (주)에스와이유 내부 시험 환경(모의 브로커·시험 DB)에서 확인한
결과이며, 실장비 연동 시험은 접속 정보 전달 이후 별도 수행 예정임.

| 시험 항목 | 조건 | 결과 |
|---|---|---|
| 구성 1안 | 모듈 직결, `deviceId` 생략 | 토픽 발신자 ID로 설비 식별, 연결 방식 "모듈 직결" 기록 |
| 구성 2안 | 사용자 PC 경유, 다건 전송 | 앞단 "게이트웨이" 등록, 설비별 분리 저장 |
| 구성 3안 | 브릿지 경유, 다건 전송 | 앞단 "브릿지" 등록, 설비별 분리 저장 |
| 1개월분 재전송 | 25,920건 / 500개 단위 52개 메시지 | 전량 적재, 약 10초 소요, 현재값·알람 영향 없음 |
| 명령 응답 시간 초과 | 대기시간 10초 | 10초 경과 시 "응답 없음" 처리 |
| 지연 응답 회수 | 14초 뒤 응답 도착 | "응답 완료"로 정상 반영 |

4.2 1분 주기·앞단당 32대·30일 기준 1개월분은 약 138만 건이며, 500개 단위로
나누면 약 2,760개 메시지가 됨. 메시지 간 200ms 이상 간격을 권장함.

## 5. 장비 측 준수 요청 사항

5.1 아래 항목은 서버가 임의로 보완할 수 없는 사항이므로 펌웨어에 반영을
요청함.

| 번호 | 항목 | 내용 |
|---|---|---|
| 1 | 재전송 표시 | 버퍼에 쌓였다 보내는 과거분에는 반드시 `"replay": true` 를 포함할 것 |
| 2 | 명령 식별자 반환 | 응답에 수신한 `cmdId` 를 그대로 넣을 것 |
| 3 | 설비 식별자 고정 | `deviceId` 는 브릿지·모듈을 교체하여도 바뀌지 않을 것 |
| 4 | 시각 동기 | NTP 동기 또는 `sync_time` 명령 수신을 지원할 것 |
| 5 | 분할 전송 | 한 메시지 500개 항목 이하, 메시지 간 200ms 이상 간격 |
| 6 | 상태 메시지 | `stat` 에 retain 설정, LWT 로 `{"online": false}` 등록 |

5.2 제5.1항 1번(재전송 표시)은 특히 중요함. 표시가 없으면 서버는 그 값을
현재 상태로 간주하므로, 1개월 전의 이상값으로 알람이 발생하고 관계자에게
문자·카카오톡이 발송됨.

## 6. 협의 요청 사항

### 6.1 절연유 유면 측정 규격 (최우선)

6.1.1 현재 서버는 유면을 2치(정상/낮음)로 저장하며, 접점(0/1)·문자열·숫자를
모두 수용함. 아래 중 어느 방식인지 확정 요청함.

| 방식 | 서버 영향 |
|---|---|
| 접점 2치 (정상/낮음) | 변경 없음 |
| 아날로그 (% 또는 mm) | 데이터 형식·임계치 체계·화면 게이지 변경 필요 |

6.1.2 아날로그인 경우 측정 범위·단위와 "낮음" 판정 기준값을 함께 회신 요청함.

### 6.2 식별자 부여 규칙

| 항목 | 확인 필요 사항 |
|---|---|
| `deviceId` | 부여 주체와 형식, 설비 교체 시 유지 여부 |
| `srcId` | 브릿지·모듈 고유 ID 형식, 시리얼 번호 사용 가능 여부 |
| RS-485 슬레이브 주소 | `deviceId` 와의 대응 관계 |

### 6.3 명령 집합 확정

6.3.1 서버는 아래 명령을 제안안으로 구현해 두었음. 지원 가능 범위와
명령어 표기를 확정 요청함.

| 명령어 | 용도 | 추가 값 |
|---|---|---|
| `ping` | 생존 확인 | 없음 |
| `read_now` | 즉시 측정 후 전송 | 없음 |
| `resend` | 지정 구간 재전송 | `from`, `to` (ISO 8601) |
| `set_interval` | 측정·전송 주기 변경 | `seconds` (10~3600) |
| `sync_time` | 장치 시계 동기 | 없음 |
| `reboot` | 장치 재시작 | 없음 |

6.3.2 명령 정의를 서버 한 곳에서 관리하므로, 확정 후 반영에 추가 공수가 들지 않음.

### 6.4 접속 정보 전달 및 방화벽 개방

6.4.1 브로커 주소·포트·계정·CA 인증서는 (주)에스와이유가 발급하여 전달함.

| 항목 | 값 |
|---|---|
| 브로커 | Mosquitto 2.0.x, 서버에 설치 완료 |
| 포트 | 8883 (TLS 필수) |
| 인증 | 계정/비밀번호. (주)에스와이유 발급 |
| 서버 인증서 | 자체 CA 발급, 고정 IP 기준으로 발급 완료 |

6.4.2 장비 접속을 위해서는 서버 방화벽에 접속 출발지 IP 대역 등록이
필요함. **㈜헤디 측 시험망 및 현장 회선의 공인 IP 대역 회신 요청함.**

6.4.3 계정은 장비 구분별로 분리 발급할 수 있음. 필요한 단위(현장 단위 /
브릿지 단위 / 모듈 단위)를 회신 요청함.

## 7. 회신 요청 사항 정리

| 번호 | 항목 | 관련 항 |
|---|---|---|
| 1 | 절연유 유면 측정 규격 (접점 / 아날로그) | 6.1 |
| 2 | `deviceId`·`srcId` 부여 규칙 | 6.2 |
| 3 | 지원 가능 명령 집합 | 6.3 |

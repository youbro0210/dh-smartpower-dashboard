# cs-engine — 수정 요청(CS) 엔진

사내 사용자가 «이것 고쳐 주세요» 를 남기면 AI가 읽고 분류합니다. 분류한 뒤에는 이렇게 처리합니다.

- **데이터 정정**: 정정안을 만들고, 관리자가 반영하거나 위험이 낮으면 바로 반영합니다.
- **프로그램 수정**: 코드 자동 수정(`autofix/`)으로 PR을 만들고, 검사를 통과하면 합친 뒤 배포까지 합니다.
- **사용 문의**: 답을 씁니다.

진행률과 예상 완료 시간을 보여 주고, 끝나면 요청자에게 알립니다.

여각(물류관리)에서 처음 만들었습니다. 프로젝트를 모르게 짜 두었으니, 다른 프로그램에는 **어댑터만 새로 쓰면** 붙습니다.

```
요청 접수 ──▶ analyzeRequest ──▶ 데이터 정정 ──▶ proposeWithTools(찾기 도구) ──▶ 검사 ──▶ 반영 / 되돌리기
 (화면)        (종류·위험·처리안)   │                                  │ decideAuto: 위험 낮음 + 안전한 칸이면 바로 반영
                                  ├─▶ 프로그램 수정 ──▶ autofix/ (GitHub Actions + Claude Code → PR → 검사)
                                  │                     │ canAutoMerge: 위험 낮음 + 검사 통과 + 파일 ≤ 5 → 합치고 배포(서버 배포기)
                                  └─▶ 사용 문의 ──▶ 답(howto 를 근거로)
진행률: progressOf / pctNow / etaText (기계 단계는 시간에 따라 오른다), react/CsProgressBar
```

## 파일

| 파일 | 하는 일 | 의존 |
|---|---|---|
| `types.ts` | 상태·종류·위험 이름, 처리 전이(TRANSITIONS), 진행 기록 이름(EVENT_LABEL) | 없음 |
| `analyze.ts` | 요청 분석(Claude, 구조화 출력). 화면 목록·자주 하는 일·업무 규칙은 `AnalyzeContext` 로 받음 | @anthropic-ai/sdk, zod |
| `propose.ts` | 정정안 만들기. 프로젝트의 **읽기 전용** 찾기 도구로 대상을 찾고, `propose_fixes` 로 정정안만 냄 | @anthropic-ai/sdk |
| `fields.ts` | 정정할 수 있는 칸 정의(EntitySpec), 값 검사(normalize·checkUpdateFields) | 없음 |
| `policy.ts` | 위험 낮음 자동 처리 기준(decideAuto·isSafeOp·canAutoMerge), 기본 설정 | 없음 |
| `progress.ts` | 진행률·예상 완료 시간 | 없음 |
| `react/CsProgressBar.tsx` · `react/progress.css` | 진행률 막대(React). `refresh` 를 주면 5초마다 상태를 다시 읽음 | react |
| `schema.sql` | 표 견본(요청·사진·진행 기록·정정안·설정) | — |

## 다른 프로그램에 붙이기

1. `cs-engine/` 과 `autofix/` 를 복사하고, `schema.sql` 로 표를 만듭니다(앞머리는 바꿔도 됩니다).
2. **분석**: `analyzeRequest({ apiKey, model, ctx: { appName, screens, howto, rules }, input })` 의 결과를 요청 줄에 저장합니다.
3. **정정**: 고칠 수 있는 칸을 `EntitySpec` 으로 적습니다. 그 칸만 고칠 수 있고 나머지는 막힙니다. 찾기 도구는 SELECT 만 하는 함수로 준비해 `proposeWithTools` 에 넘깁니다. 반영은 프로젝트가 한 트랜잭션으로 합니다. 반영 전 값을 남기고, 정정안을 만든 뒤 값이 바뀌었으면 막습니다.
4. **자동 처리**: `decideAuto(analysis, settings)` 와 안전한 칸 목록(`SafeFields`)으로 바로 반영할지 정합니다. 프로그램 수정이면 `autofix/` 로 보내고, PR 알림을 받으면 `canAutoMerge` 로 합칠지 정합니다.
5. **화면**: 요청 접수(구분·화면·사진 붙여넣기), 반영 확인(상태 탭·찾기·진행 단계·진행률·되물을 것·정정안·자동 수정), 설정 켜고 끄기를 둡니다. 여각 화면 `app/(main)/cs/*` 를 견본으로 쓰면 됩니다.
6. **알림**: 상태가 바뀌면 요청자에게 알립니다(여각은 텔레그램, 안 이었으면 화면 위 종). 보낸 사실은 진행 기록에 남깁니다.

## 안전장치

- 요청 글과 사진 속 글은 자료로만 다룹니다(모든 프롬프트에 규칙을 넣습니다). AI에게는 바꾸는 도구가 없습니다.
- 자동 반영은 **위험 낮음 · 처리안 분명 · 되물을 것 없음 · 안전한 칸** 이 모두 맞을 때만 합니다. 날짜·수량·취소·돈은 관리자가 합니다.
- 자동 합치기·배포는 **위험 낮음으로 자동으로 보낸 작업 · 검사 모두 통과 · 파일 5개 이하** 일 때만 합니다. 관리자가 끌 수 있습니다.
- 모든 정정은 되돌릴 수 있습니다. 반영한 값 그대로일 때만 되돌립니다.

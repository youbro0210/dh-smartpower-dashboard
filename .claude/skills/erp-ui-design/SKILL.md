# 업무용 화면 디자인 규칙

이 스킬은 국내 기업용 업무 시스템(더존, SAP, 그룹웨어 수준)의 화면 품질을 목표로 한다.
화면은 "제품 홍보 페이지"가 아니라 "매일 8시간 쓰는 업무 도구"다. 정보 밀도, 정렬, 가독성이 장식보다 우선한다.

작업 순서:
1. 코드를 쓰기 전에 `references/tokens.css`를 프로젝트 전역 스타일에 반영한다 (Tailwind 프로젝트면 `references/tailwind-preset.js`도 적용).
2. 화면 유형에 맞는 구조를 `references/patterns.md`에서 가져온다.
3. 완료 전 아래 "금지 패턴"과 "완료 점검표"로 결과물을 직접 검사하고 위반 사항을 고친다.

## 1. 기본 원칙

- 바탕은 항상 흰색(#FFFFFF). 다크 테마, 회색 페이지 배경 위에 흰 카드 띄우기 금지.
- 영역 구분은 그림자·카드가 아니라 **1px 실선**과 **배경색이 옅은 헤더 행**으로 한다.
- 모서리: 기본 0~2px, 최대 4px. `rounded-lg` 이상 금지.
- 기본 글자 13~14px, 표 본문 13px. 큰 제목(32px 이상)과 넓은 여백 금지.
- 색은 절제: 본문 회색조 + 주색상(진한 남색) 1개 + 상태색(빨강·초록)은 숫자/글자에만.
- 숫자·금액·수량은 오른쪽 정렬, `tabular-nums`, 천 단위 콤마. 날짜는 `YYYY-MM-DD`.
- 모든 행·열·입력칸의 높이와 기준선을 맞춘다. 정렬이 1px이라도 어긋나면 고친다.

## 2. 금지 패턴 (AI가 만든 티)

아래는 하나라도 있으면 안 된다.

| 구분 | 금지 |
|---|---|
| 형태 | `rounded-xl`, `rounded-2xl`, `rounded-full` 버튼·카드, 알약형 배지/태그 |
| 효과 | `shadow-md` 이상 그림자, 그라데이션, 글래스모피즘(`backdrop-blur`), 네온·발광 |
| 색 | 보라/인디고/핑크 계열 주색상, 색 배경 배지(초록 알약 "완료" 등), 파스텔 아이콘 원 |
| 구성 | 통계 카드 4개 나열 + 아이콘 원, 히어로 섹션, 큰 환영 문구("안녕하세요 👋") |
| 아이콘 | 이모지, 모든 메뉴·버튼에 아이콘 붙이기, 장식용 일러스트 |
| 문구 | 조작 안내 문구("[조회]를 눌러야 반영됩니다", "여기에 입력하세요"), 빈 화면의 친절한 설명문, 마케팅 문구 |
| 레이아웃 | 화면 중앙 좁은 카드(`max-w-md mx-auto`)로 업무 화면 구성, 과도한 여백(`p-8` 이상), 카드 그리드로 목록 표시 |
| 폰트 | Inter·시스템 기본 폰트만 사용 (한글은 Pretendard 지정) |
| 모션 | hover 시 확대·튀는 애니메이션, 페이지 진입 페이드 연출 |

빈 데이터는 표 안에 "조회된 데이터가 없습니다." 한 줄만 회색으로 표시한다.
상태값은 배지 대신 글자색만 사용한다 (예: 지연 = 빨간 글자, 완료 = 기본 글자).

## 3. 화면 골격

```
┌──────────────────────────────────────────────┐
│ 상단바 48px: 로고 | 시스템명        사용자 | 로그아웃 │  ← 흰 바탕, 하단 1px 선
├────────┬─────────────────────────────────────┤
│ 좌측   │ 화면 제목 (16px, 600)      [버튼들] │  ← 제목 행 40px, 하단 선
│ 메뉴   ├─────────────────────────────────────┤
│ 200px  │ 조회조건 영역 (라벨-입력 격자, 실선 테두리) │
│        ├─────────────────────────────────────┤
│        │ 건수 표시            엑셀 | 인쇄      │
│        │ ┌ 데이터 표 (실선, 헤더 회색) ──────┐ │
│        │ └──────────────────────────────────┘ │
│        │ 페이지 이동                           │
└────────┴─────────────────────────────────────┘
```

- 메뉴: 글자 위주, 선택된 항목은 왼쪽 3px 주색상 선 + 옅은 배경. 아이콘은 1단 메뉴에만 선택적으로.
- 버튼 위치: 화면 제목 행 오른쪽에 저장·삭제 등 주요 동작, 표 위 오른쪽에 엑셀·인쇄.
- 버튼 순서: [조회] [신규] [저장] [삭제] — 주 동작 1개만 주색상 채움, 나머지는 테두리 버튼.

## 4. 표 (가장 중요)

- `border-collapse: collapse`, 모든 셀 1px 실선(#D0D5DD).
- 헤더: 배경 #F2F4F7, 글자 600, 가운데 정렬, 높이 34px.
- 본문 행 높이 32px, 좌우 패딩 8px. 줄무늬(zebra) 금지, hover 시 #F5F8FC.
- 선택 행: 배경 #E8F0FA.
- 문자 왼쪽 / 숫자 오른쪽 / 코드·날짜·상태 가운데 정렬.
- 합계 행: 배경 #F9FAFB, 글자 600, 위쪽 선 진하게(#98A2B3).
- 헤더 고정(`position: sticky; top: 0`), 열 너비는 내용 기준으로 지정.
- 상세 구현은 `references/patterns.md`의 "데이터 표" 참조.

## 5. 입력폼

- 라벨-입력 격자형 표(`th` 라벨 + `td` 입력)로 구성. 라벨 칸 배경 #F2F4F7, 너비 120px, 오른쪽 정렬 아님(왼쪽 정렬).
- 입력칸 높이 30px, 테두리 1px #D0D5DD, 모서리 2px, focus 시 테두리만 주색상.
- 필수 항목은 라벨 앞 빨간 `*` 한 글자만.
- placeholder에 설명 문장 금지. 형식 힌트가 꼭 필요하면 `YYYY-MM-DD` 수준만.
- 오류는 입력칸 아래 12px 빨간 글자 한 줄.

## 6. 대시보드

- 상단 지표는 카드가 아니라 **한 줄 요약 표**(지표명 | 값 | 전월 대비)로.
- 차트는 흰 바탕, 격자선 옅게, 범례 상단 오른쪽, 색은 주색상 계열 2~3개만. 3D·도넛 남용 금지.
- 영역 제목은 14px 600 + 하단 1px 선. 영역 사이 간격 16px.

## 7. 완료 점검표

결과물을 넘기기 전에 코드를 다시 읽고 확인한다.

- [ ] 페이지·영역 배경이 모두 흰색인가
- [ ] `rounded-lg|xl|2xl|full`, `shadow-md|lg|xl`, `gradient`, `backdrop-blur`, `indigo|purple|violet|pink` 클래스가 없는가 (grep으로 확인)
- [ ] 이모지와 조작 안내 문구가 없는가
- [ ] 목록은 카드가 아니라 실선 표인가
- [ ] 숫자 오른쪽 정렬·콤마·`tabular-nums`가 적용됐는가
- [ ] 같은 행의 입력칸·버튼 높이가 동일한가
- [ ] 한글 폰트가 Pretendard로 지정됐는가
- [ ] 오탈자가 없는가

점검용 명령:
```bash
grep -rnE "rounded-(lg|xl|2xl|3xl|full)|shadow-(md|lg|xl|2xl)|gradient|backdrop-blur|(indigo|purple|violet|pink)-[0-9]" src app components 2>/dev/null
```
결과가 나오면 해당 부분을 이 규칙에 맞게 수정한다.
